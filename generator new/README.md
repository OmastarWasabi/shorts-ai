# Generator — Python

Самостоятельный Python-проект для генерации голоса и изображений, выравнивания речи и монтажа видео с субтитрами.

## Начало работы

Откройте эту папку в редакторе или перейдите в неё из терминала:

```bash
cd "/Users/omastarw/Documents/shorts-ai/generator new"
```

Папки внутри проекта:

| Папка | Содержимое |
| --- | --- |
| `src/shorts_ai/` | Основной Python-код |
| `generator/` | `.env`, исходные тексты и указатель на текущую папку ролика |
| `tests/` | Тесты и небольшие тестовые данные |
| `.venv/` | Окружение генерации и монтажа |
| `.venv-timing/` | Полное окружение, включая WhisperX |

Исходные `story.txt`, `prompts.txt` и настройки `.env` находятся в `generator/`. Есть два способа запуска: полный автоматический `run` и отдельные команды для ручной работы. В ручном режиме каталог результата и имя папки задаются в команде:

```bash
.venv/bin/python -m shorts_ai generate --output-dir "./videos/Почему шины чёрные"
```

`--output-dir` обязателен при каждом вызове `generate`. Без него команда завершается с ошибкой аргументов, даже если прошлый ролик уже выбран. Последняя часть пути — имя папки; автоматические номера не добавляются. Относительный путь считается от текущей папки терминала, абсолютный используется как есть.

Папка создаётся вместе с родительскими каталогами. В неё копируются `story.txt`, `prompts.txt` и `scenes.json`, если он есть. Голос, картинки, новая разметка, тайминги и MP4 сохраняются в этой папке. `.env` читается из исходного `generator/`.

Абсолютный путь результата записывается в `generator/.current_run`. Команды `align` и `montage` автоматически продолжают этот ролик. Отдельные `voice` и `images` также продолжают работу в текущей папке. Если оба генератора отключены, `--output-dir` всё равно требуется, но папка не создаётся.

## Полный автоматический запуск

После подготовки исходных текстов и установки полного окружения:

```bash
FFMPEG_BIN=/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg \
  .venv-timing/bin/python -m shorts_ai run
```

`run` читает `.env` из `generator/`, создаёт отдельную папку по дате и времени в `~/Documents/shorts-ai/shorts/ai/` и выполняет весь цикл:

1. Копирует `story.txt`, `prompts.txt` и `scenes.json`, если он есть.
2. Генерирует голос и картинки параллельно и дожидается завершения обоих генераторов.
3. Создаёт разметку сцен при её отсутствии и определяет тайминги слов через WhisperX.
4. Собирает `final.mp4` с движением камеры и субтитрами.

Следующий этап начинается после завершения предыдущего, без фиксированных пауз. Все этапы используют копии исходников в одной папке ролика. Например:

```text
~/Documents/shorts-ai/shorts/ai/2026-10-28_12-30-45_123456/
├── story.txt
├── prompts.txt
├── scenes.json
├── voice.mp3
├── images/
├── timeline.json
└── final.mp4
```

Программа выводит начало, завершение и длительность каждого этапа, общее время и путь готового ролика. Пример:

```text
Генерация начата.
Генерация завершена: 02:15
Выравнивание начато.
Выравнивание завершено: 00:18
Монтаж начат.
Монтаж завершён: 00:24
Всего: 03:02
Готовый ролик: .../final.mp4
```

Формат длительности — минуты:секунды. Время генерации относится к совместному этапу голоса и картинок; общее время также включает подготовку папки. Эти числа приведены как пример, а не оценка скорости.

При ошибке или Ctrl+C следующие этапы не запускаются. Успешно сохранённые материалы остаются в папке ролика, путь к которой записан в `generator/.current_run`. Их можно продолжить обрабатывать отдельными командами. Новый `run` всегда создаёт новую папку.

Для полного цикла нового ролика включите `GENERATE_VOICE=true` и `GENERATE_IMAGES=true`: отключённые генераторы не создадут необходимые материалы в новой папке. Старые голос и картинки из других папок автоматически не подхватываются. Для WhisperX используется уже скачанная модель; порядок первой загрузки описан ниже.

Свой каталог исходников можно выбрать существующим аргументом перед командой:

```bash
FFMPEG_BIN=/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg \
  .venv-timing/bin/python -m shorts_ai --project-dir "/путь/к/исходникам" run
```

## Отдельные команды

Из этой папки:

```bash
# Генерации по двум флагам в generator/.env
.venv/bin/python -m shorts_ai generate --output-dir "./videos/Почему шины чёрные"

# Только голос или только изображения
.venv/bin/python -m shorts_ai voice
.venv/bin/python -m shorts_ai images

# Тайминги текущего ролика
.venv-timing/bin/python -m shorts_ai align

# Базовый монтаж: равномерные сцены, без субтитров
.venv/bin/python -m shorts_ai montage --output basic.mp4

# Монтаж по речи с субтитрами
FFMPEG_BIN=/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg \
  .venv/bin/python -m shorts_ai montage --timeline timeline.json --output timed.mp4

# Те же тайминги без субтитров
.venv/bin/python -m shorts_ai montage --timeline timeline.json \
  --no-subtitles --output plain.mp4
```

Результаты сохраняются в папке, переданной через `--output-dir`. При повторном указании той же папки готовые голос и картинки пропускаются. Для нового ролика укажите другой путь: изменение исходных текстов не обновляет существующие голос/PNG автоматически. Монтаж требует новое имя MP4. Для обновления существующего JSON есть `align --force`.

После `run` эти же команды продолжают работу с автоматически созданной папкой. Если меняете текст для повторной озвучки, редактируйте `story.txt` именно в папке ролика: изменения исходного `generator/story.txt` в уже созданную копию не переносятся. После новой озвучки пересчитайте таймлайн. Для другого имени аудио используйте `voice --output voice_v2.mp3`, затем передайте `--audio voice_v2.mp3` в `align` и `montage`.

Другой каталог исходников можно указать перед подкомандой:

```bash
.venv/bin/python -m shorts_ai --project-dir "/путь/к/исходникам" generate \
  --output-dir "/путь/к/роликам/Название ролика"
```

Чтобы вернуться к более раннему ролику, укажите его папку напрямую:

```bash
.venv-timing/bin/python -m shorts_ai --project-dir "./videos/Почему шины чёрные" align
```

Относительные пути файлов в `voice`, `images`, `align` и `montage` отсчитываются от текущего каталога ролика. Исключение — `--music`: как и `generate --output-dir`, он отсчитывается от папки терминала. Справка доступна через `--help` у каждой команды.

## Фоновая музыка

Добавьте `--music` к полному пайплайну:

```bash
FFMPEG_BIN=/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg \
  .venv-timing/bin/python -m shorts_ai run --music "/путь/к/музыке.mp3"
```

Или запустите отдельный монтаж уже готовых материалов текущего ролика:

```bash
FFMPEG_BIN=/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg \
  .venv/bin/python -m shorts_ai montage --timeline timeline.json \
  --music "/путь/к/музыке.mp3" --output final_music.mp4
```

По умолчанию `montage` выбирает последнюю папку ролика из `generator/.current_run`. Этот указатель обновляется командами `run` и `generate`.

Для монтажа конкретного ролика укажите **папку** через `--project-dir` перед `montage`. Пример для ролика `ples`, запуск из папки `generator new`:

```bash
FFMPEG_BIN=/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg \
  .venv/bin/python -m shorts_ai \
  --project-dir "/Users/omastarw/Documents/shorts-ai/shorts/ai/ples" \
  montage \
  --timeline timeline.json \
  --music "/Users/omastarw/Documents/shorts-ai/shorts/ai/soft.mp3" \
  --output final_music.mp4
```

В `--project-dir` передавайте путь до `ples`, без `/final.mp4`: аргумент ожидает каталог. Из него берутся `images/`, `voice.mp3` и `timeline.json`, туда же сохраняется `final_music.mp4`.

Это повторный монтаж из картинок и озвучки; генерация и выравнивание заново не запускаются. Выберите новое имя MP4, если старый файл уже существует. Для базового монтажа без таймлайна просто уберите `--timeline timeline.json`; музыка также работает с `--no-subtitles`.

Музыка смешивается с озвучкой в одну аудиодорожку на уровне 10% от исходной громкости трека. Короткий трек повторяется, длинный обрезается по длительности озвучки. Последние две секунды музыка плавно затухает; для ролика короче двух секунд затухание занимает всю его длину. Громкость озвучки не уменьшается.

Путь `--music` в обеих командах отсчитывается от текущей папки терминала, поддерживаются абсолютные пути и `~`. Например, `--music "./music/background.mp3"` выбирает трек из папки `music/` рядом с этим README, если команда запущена из корня проекта. Исходная музыка используется по указанному пути и не копируется в папку ролика; готовый микс сохраняется внутри MP4. Без `--music` монтаж работает как раньше.

## Настройки и входные файлы

Шаблон настроек — [generator/.env.example](generator/.env.example). Основные переключатели:

```dotenv
GENERATE_VOICE=true
GENERATE_IMAGES=true
```

Они действуют на `generate` и `run`; команды `voice` / `images` явно запускают свою генерацию. Для новых запросов нужны соответствующие `FISH_API_KEY` / `OPENAI_API_KEY`. Переменные процесса имеют приоритет над `.env`. Запросы генерации платные; тесты не подтверждают доступность текущих ключей, моделей или квоты.

`story.txt` — непустой UTF-8 текст. `prompts.txt` начинается с `[01]`: название ролика в этом файле больше не нужно. Далее идут маркеры `[02]`, `[03]`, … на отдельных строках и многострочные промпты после них, без пропусков/повторов номеров.

Если `scenes.json` отсутствует, `align` создаёт его автоматически: **один абзац сценария, отделённый пустой строкой, соответствует одному промпту и одной картинке**. Перенос строки внутри абзаца новую сцену не создаёт. Количество абзацев должно совпадать с количеством промптов; иначе программа выдаёт объяснение и не угадывает границы. Авторазметка использует русский язык и не вызывает API. Для другого файла промптов есть `align --prompts путь`.

Существующий `scenes.json` используется как есть; авторазметка его не заменяет. Он содержит `version: 1`, `language: "ru"` и список `scenes` с `number` и `text`; тексты сцен должны совпадать со сценарием по словам и порядку. Ручная разметка позволяет выбрать другие границы сцен или язык. `--force` обновляет только тайминги, а не разметку сцен.

Для монтажа нужны FFmpeg и ffprobe в PATH. Для субтитров требуется фильтр `ass` / libass; на текущем Mac подходит указанный выше `ffmpeg-full`. `FFMPEG_BIN` задаёт путь к FFmpeg; в примерах он передаётся в окружении команды. Отдельные команды `align` и `montage` сами не читают `.env`. Монтаж выдаёт H.264 + AAC, 1080×1920, 30 fps, с шестью вариантами движения камеры. Субтитры сгруппированы по словам и подсвечиваются по мере речи.

WhisperX использует модель из общего локального кэша. Для первого скачивания на другом компьютере добавьте `align --download-model`. Озвучка ограничена 180 секундами. Монтаж готового JSON не требует WhisperX; Go для этого проекта не нужен.

## Установка заново

Проверенная среда — Python 3.13 / macOS arm64. Окружения необходимо создавать на новом месте, а не переносить готовые папки:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
.venv/bin/python -m pip install --no-deps -e .
.venv/bin/python -m pip check

python3 -m venv .venv-timing
.venv-timing/bin/python -m pip install -r requirements-timing.lock.txt
.venv-timing/bin/python -m pip install --no-deps -e '.[timing]'
.venv-timing/bin/python -m pip check
```

Полное окружение `.venv-timing` также выполняет все команды генерации и монтажа. Конкретный путь этой папки программе не нужен; после её переноса создайте окружения заново. Общий кэш модели — стандартная внешняя зависимость WhisperX, не ссылка на прежний проект.

## Проверка

Полный набор в базовом окружении:

```bash
FFMPEG_BIN=/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg \
  .venv/bin/python -m unittest discover -s tests -p 'test_*.py'
```

Тот же набор в полном окружении:

```bash
FFMPEG_BIN=/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg \
  .venv-timing/bin/python -m unittest discover -s tests -p 'test_*.py'
```

Быстрая проверка папок и общего пайплайна:

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_runs.py' -v
FFMPEG_BIN=/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg \
  .venv/bin/python -m unittest discover -s tests -p 'test_pipeline.py' -v
```

Тесты проверяют копии исходников, текущую папку, обязательный `--output-dir` ручной генерации, разные папки автозапусков, порядок и ожидание этапов, длительности, остановку после ошибки/прерывания и создание MP4 с субтитрами. Сквозной тест выполняет `run` с подставным API и результатом модели; разметка сцен, JSON, сохранение и FFmpeg работают по-настоящему во временной папке. Проверяется также повторное использование готовых материалов отдельными командами.

Платные запросы и скачивание модели в тестах не выполняются. Интеграционные тесты явно пропускаются, если FFmpeg/ffprobe или libass недоступны; для полного прогона используйте установленный `ffmpeg-full`. MIT-уведомление использованной логики монтажа включено в пакет: [NOTICE](src/shorts_ai/NOTICE).
